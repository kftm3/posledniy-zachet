# Последний зачёт

Браузерная визуальная новелла на TypeScript и Vite.

## Разработка

Node.js 22+ и npm. CI использует Node 22; облачная среда проверена на Node 24.

```bash
npm ci
npm run dev
```

Редактируйте `src/`, `index.html` и `public/`. `public` — единственный исходный каталог статических ресурсов. `dist` создаётся автоматически при сборке и не хранится в Git, как и `node_modules`.

```bash
npm run build
npm run test:assets
npm run preview
```

Production-сборка использует базовый путь `/posledniy-zachet/`. GitHub Actions собирает проект из исходников, проверяет ссылки на ресурсы и публикует `dist` в GitHub Pages. В настройках Pages должен быть выбран источник **GitHub Actions**.

## Браузерные проверки

```bash
npx playwright install chromium
npm test
```

Тесты сами собирают игру и запускают preview на порту 4175. Если Chromium уже установлен, можно указать путь:

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm test
```

Мобильные сценарии находятся в `tests/mobile.spec.ts`: касания, компоновка при 874×353, 812×320 и 874×402, отступы iPhone, музыка, зачёт, итоги и достижения. Для отдельного прогона движком WebKit:

```bash
npx playwright install webkit
npx playwright test tests/mobile.spec.ts --browser=webkit
```

Телефонная компоновка вынесена в `src/mobile.css` и включается только при `(pointer: coarse) and (max-width: 1100px)`. Такой же запрос использует `src/mobile.ts` для подсказки о повороте экрана и мобильного запуска музыки. Размеры учитывают `dvh` и `safe-area-inset-*`. Изменяя телефонные экраны, сохраняйте этот общий критерий; исходные стили ПК остаются в `src/style.css`.

Общий экран достижений для ПК и телефона оформляется в `src/achievements.css`: полученные карточки подсвечены, закрытые затемнены. После завершения первого прохождения в главном меню появляется «Мои достижения». Экран читает сохранённый прогресс и возвращает игрока к месту открытия: в меню или к итогам. До первого завершения эта кнопка скрыта, ресурсы достижений при открытии меню не загружаются.

На телефоне круглая кнопка «?» на выборе персонажа открывает ввод найденного чит-кода. Применение использует ту же логику, что клавиатурный ввод на ПК, и сразу выбирает разблокированного героя. Повторный ввод отключает код. Поле учитывает доступную область экрана при открытой клавиатуре; регистр и пробелы по краям не важны.

## Ресурсы

Полноразмерные изображения используют WebP **без потерь**, миниатюры — `srcset`. Фоны коридора и аудитории подготавливаются уже при вводе данных; на билете добавляются первые нужные спрайты и музыка. На стартовом экране поздние сцены и музыка не скачиваются. Переходы дожидаются декодирования нужных фонов; при медленной сети отображается статус подготовки. Новые аудиообъекты создавайте через `createAudio` из `src/media.ts`, чтобы не загружать поздние сцены при открытии меню.

Загрузкой ресурсов управляет `src/asset-loading.ts`: общая очередь с двумя фоновыми загрузками, кеш запросов, безопасная смена спрайтов и повторная попытка после ошибки. Используйте `prepareAudio`, чтобы повторно не назначать тот же источник и не сбрасывать буфер музыки.

Портрет студенческого билета использует `card-256.webp`/`card-512.webp` через `srcset` вместо полноразмерной карточки. Он подготавливается по нажатию «Продолжить» на выборе персонажа и повторно использует кеш миниатюр. При открытии билета источник готового изображения не назначается заново.

Итоги подготавливаются с начала зачёта, достижения — после третьего ответа. Открытие достижений ожидает только фон; панель формируется HTML/CSS. Все иконки ждать не нужно: до их готовности остаются пустые места без эмодзи. Видео подготавливаются через `prepareMedia` до перехода, с повторным использованием того же элемента. Ролики сжаты отдельно с согласия автора; звук, разрешение и временные метки кадров сохранены. Не перекодируйте уже сжатые видео повторно: для новых вариантов используйте исходники из Git до оптимизации.

Музыка аудитории использует `C418-Aria_Math-clean.mp3`: из исходного файла удалены посторонний HTML-префикс и встроенная обложка, сами MPEG-кадры сохранены. Новый URL исключает старую повреждённую версию из браузерного кеша. `test:assets` проверяет сигнатуру MP3; браузерные тесты — HTTP Range, декодирование и продвижение воспроизведения.

Переходами управляет `src/transitions.ts`: подготовка изображения, полное затемнение, смена сцены, ожидание отрисовки и плавное раскрытие. Модуль ожидает фактическое завершение CSS-перехода, учитывает `prefers-reduced-motion`. Для новых переходов используйте его вместо отдельных таймеров. Кеш декодированных изображений ограничен расчётными 32 МиБ; общий расход памяти браузера может быть больше.

Кадры камео подготавливаются перед соответствующим вопросом. Для коротких сюжетных эффектов используйте `AudioCue` из `src/cue-audio.ts`: вызовите `prepare()` заранее, а `play()` — на нужной реплике. `stop()` отменяет отложенный запуск. Музыка остаётся потоковой. Индикатор с фразами на выборе персонажа управляется `src/character-loading.ts` и очищает таймеры после загрузки или смены экрана.

Для обработки новых PNG установите Pillow с поддержкой WebP и запустите:

```bash
python3 scripts/optimize-images.py
python3 scripts/generate-thumbnails.py
npm run build
npm run test:assets
```

Конвертер проверяет совпадение пикселей перед удалением PNG и обновляет расширения в ссылках проекта, в том числе шаблонных. Перед его запуском сохраните исходники в Git. Генератор миниатюр не заменяет полноразмерные изображения.

Результаты и ограничения проверки: [PERFORMANCE.md](PERFORMANCE.md).

Диалоги на ПК используют общую раскладку с кнопкой продолжения справа внизу. На зачёте вопрос, ответы и действия занимают отдельные области; итоговая зачётка сохраняет пропорции при ограничении шириной и высотой экрана. Мобильные правила остаются в `src/mobile.css`, правила диалогов ПК — в `src/scene-layout.css`.
